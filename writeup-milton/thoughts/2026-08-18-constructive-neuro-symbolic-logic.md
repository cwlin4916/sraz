# Constructive neuro-symbolic logic: grammars vs. templates

**PG:** I have worked with logical neural networks, and they suffer from what I call the
"template problem", which is that even though you can refine them differentiably (e.g.,
learn from data that AND(a,b,c) really only depends on a and b and can thus be simplified
to AND(a,b)), you still have to specify the basic structure that defines "all possible
models" up front (the "template"). A more constructive approach would treat logic as a
grammar and build expressions from scratch; but this invites the combinatorial explosion.
Can you comment more on how neural networks can be used in this second, "constructive" case?

When we rely on differentiable templates (like Logical Neural Networks or ∂ILP), we are
essentially doing parameter optimization over a pre-defined super-graph. We avoid
combinatorial explosion by paying a heavy tax: specifying the maximum template depth,
clause arity, and specific predicate topologies up front. [1]

To shift to a constructive approach — where the neural network builds a logical expression
from scratch using a grammar — we must move from parameter optimization to discrete
structure synthesis.

Here is how neural networks are currently being used, and can be used, to tame the
combinatorial explosion in that exact generative context. [2]

## 1. Neural policy-guided tree search (RL + grammar)

Instead of searching blindly, the construction of a logic program is framed as a Markov
Decision Process (MDP). The state is the current partial expression tree, and the action is
selecting a production rule from the logic grammar.

- **The AlphaZero model:** Systems use a combination of Monte Carlo Tree Search (MCTS) and
  a policy/value neural network. [3]
- **The neural role:** The policy network outputs a probability distribution over the valid
  grammar rules at the current node, effectively narrowing the branching factor from dozens
  down to the top 2 or 3 most viable paths. The value network evaluates the partial tree,
  allowing the search to back up early if a path is a dead end. [4]
- **Why it beats templates:** It does not require a fixed maximum architecture. If the
  neural network learns structural "intuition" (e.g., that a recursive base case usually
  needs to be bound early), it can construct deep, narrow structures that a rigid template
  could never accommodate.

## 2. Autoregressive sequence-to-sequence (transformers)

Instead of treating logic as a tree, it can be treated as a serialized token string governed
by a formal grammar.

- **Syntax-directed decoding:** A Transformer (like a T5 or custom decoder-only model) is
  trained to generate the logic program token-by-token. To ensure it doesn't output invalid
  code, the model's vocabulary distribution at each step is masked by a formal grammar state
  machine. [5, 6]
- **Latent search:** The combinatorial search is shifted into the continuous latent space of
  the Transformer. The model acts as a "proposal mechanism." Instead of testing millions of
  permutations, it samples 10 or 100 highly coherent, grammatically correct candidate
  expressions based on context. [7]
- **The bottleneck:** This requires training data (pairs of problems and their corresponding
  logical expressions). However, this can be bootstrapped using self-play or synthetic
  datasets generated by smaller, brute-force symbolic solvers. [8]

## 3. Tree-structured neural networks & graph grammar networks

To avoid flattening trees into strings, constructive models can utilize architectures that
natively match the topology of logic.

- **Tree-RNNs and Tree-LSTMs:** These networks grow dynamically. The neural network contains
  modules for specific logical operators (an AND module, an OR module). The network actively
  decides whether to merge two child nodes into a parent operator node based on vector
  representations of the sub-expressions. [9, 10]
- **Graph grammar networks:** These models predict graph-rewriting rules. They start with a
  start symbol and use a neural network to choose which node to expand next and which
  production rule to apply, embedding the structural constraints directly into the network's
  action space. [11]

## 4. Differentiable search spaces (differentiable architecture search)

Borrowing from Neural Architecture Search (NAS) in deep learning, some constructive
approaches try to bridge the gap between building a structure and differentiating it.

- **Continuous relaxation of trees:** Rather than hard-selecting a grammar rule, you create
  a soft selection where a node is a weighted mixture of all possible grammar operations
  (e.g., $0.7 \text{ AND} + 0.2 \text{ OR} + 0.1 \text{ NOT}$).
- **Pruning to construct:** You start with an exponentially wide but shallow grammar tree.
  As gradient descent progresses, the weights polarize (driven by sparsity penalties like
  $L_1$ regularization or Gumbel-Softmax). Branches with near-zero weights are permanently
  pruned, and new uninitialized layers are "budded" or appended onto the winning branches,
  letting the tree grow dynamically. [12]

## Comparison of constructive neural approaches

| Strategy | Core mechanism | How it fights explosion | Main limitation |
|---|---|---|---|
| RL + MCTS | Policy network picks grammar rules | Cuts branching factor dramatically | Slow exploration in early training |
| Transformer + grammar mask | Autoregressive token generation | Samples likely candidates instantly | Hallucinations; needs massive pre-training |
| Tree-RNNs | Dynamic neural node merging | Operates directly on structural embeddings | Hard to train via standard backpropagation |
| Dynamic differentiable NAS | Growing trees via soft-max selection | Blends optimization with structural growth | Memory intensive; scales poorly past shallow depths |
